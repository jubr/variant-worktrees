## Why

Cutting a release is a manual chain: bump the lockstep version, write the changelog entries, commit, push, and open a pull request. The changelogs are curated by hand, so a release's pull requests are missing from them unless someone remembers to copy them. Separately, the extension README shows a broken image on the Cursor and Open VSX extension pages, and the tagline needs a shorter one-liner.

## What Changes

- New `task release:prepare` that, from an up-to-date clean `main`, bumps the patch version (`task version:incr:patch`), writes GitHub-generated release notes into every `CHANGELOG*.md`, commits on `release/v<version>`, pushes, and opens a pull request to `main`. It does not tag and does not merge: `ci-release.yaml` already tags `v<version>` at the merge commit.
- Each changelog gets a `## [<version>] - <date>` section: the former `Unreleased` bullets, then a `### Release notes` list of the pull requests since the previous release, generated by `gh api .../releases/generate-notes`. `Unreleased` stays above it, empty.
- The pieces are tasks, not a skill: `task release:check`, `task version:incr:patch`, `task release:changelog`, `task release:pr`. `task release:prepare` calls them in order.
- The `variant-vscode` package README drops its `![Variant Worktrees](media/icon-256.png)` line: a repository-relative image does not resolve on the extension pages and renders broken. The repository README keeps its icon.
- The tagline and manifest `description` of `variant-vscode` become `Isolated work+db for agents+yourself :: watches, seed, implode :: cli, mcp & vscode`.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `meta/release-artifacts`: adds release preparation requirements (`task release:prepare`, changelog release notes, release pull request).
- `docs/readmes`: the extension description changes, and the extension README embeds no repository-relative image.

## Impact

- `Taskfile.yaml`, new `scripts/release-changelog.ts` and `scripts/release-prepare.ts` with co-located specs.
- `CHANGELOG.md`, `packages/variant-vscode/CHANGELOG.md`, `packages/chat-renamer-vscode/CHANGELOG.md` (format of new sections only; existing text untouched).
- `packages/variant-vscode/README.md`, root `README.md`, `packages/variant-vscode/package.json`, `packages/variant-vscode/src/readme.spec.ts`.
- `CONTRIBUTING.md` (Releasing).
- [specs/meta/release-artifacts](../../specs/meta/release-artifacts/spec.md), [specs/docs/readmes](../../specs/docs/readmes/spec.md).

## Non-goals

- Tagging from `release:prepare`, merging the pull request, or publishing extensions.
- Changing how the GitHub Release body is produced (`--generate-notes` stays); the `keep-a-changelog` change owns that.
- A skill or agent-only workflow: a human runs the same task.
- Minor and major bumps.
